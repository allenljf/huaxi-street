調研日：2026-11-06（Asia/Taipei）。狀態：研究提案，未實作、未回測、未定案。
使用者已確認：數月到數年的長期分批投入；網站每天更新；不使用 LLM；確認方案後才實作。
資料源另見 [資料來源調研](data-sources-2026-11-06.md)。

## 結論與可選方向

1. **建議：免費混合來源＋固定規則＋靜態網站。** GitHub Actions 執行 Python 資料整理和評分，產生 JSON 與靜態網頁，放 GitHub Pages 或 Cloudflare Pages。不需常駐伺服器、資料庫或 LLM API；但資料來源可用性和再散布權需要分別處理。
2. **全用官方資料。** 來源可追溯，但跨國交易所的歷史 OHLC、機器下載和授權並不一致，無法承諾所有標的都免費且可公開重製。
3. **全部用 Yahoo/yfinance。** 個人研究起步最簡單，但非官方穩定 API，不適合承諾服務品質或直接推定可公開再散布。

這三種是待選方案，並非使用者已批准的設計。先做資料可用性驗證，再決定公開頁面能放哪些數值；只顯示衍生分數也不能自動推定豁免資料條款。

## 網路上常見的組合，與適合本案的部分

- TradingView Technical Ratings 將 26 個指標分為均線與振盪指標，再綜合評等；是一個可重現、非 LLM 的參考，但不是已證明最優策略。[原始說明](https://www.tradingview.com/support/solutions/43000614331-technical-ratings/)
- Schwab 示範 ADX 搭配 RSI：先辨識趨勢強弱，再看進出場條件。ADX 強不代表上漲，必須搭配方向。[Schwab](https://www.schwab.com/learn/story/spot-and-stick-to-trends-with-adx-and-rsi)
- RSI 30/70 是常見超賣／超買界線，但強勢或弱勢行情可能長期停留極端區。[Fidelity RSI](https://www.fidelity.com/learning-center/trading-investing/technical-analysis/technical-indicator-guide/RSI)
- 50/200 日均線交叉是常見長期趨勢訊號；本案提議固定採 SMA，避免 EMA/SMA 混用。[StockCharts](https://chartschool.stockcharts.com/table-of-contents/trading-strategies-and-models/trading-strategies/moving-average-trading-strategies/trading-using-the-golden-cross)
- ADX 高於 25 常被視為有趨勢，低於 20 常被視為無明確趨勢，20–25 保留為過渡區。[Fidelity ADX](https://www.fidelity.com/viewpoints/active-investor/average-directional-index-adx)
- 定期投入的價值包括降低擇時的心理負擔。新增指標策略應與相同現金流的固定投入基準比較，而不是先假設比定期定額好。[Fidelity 定期投入](https://www.fidelity.com/learning-center/trading-investing/dollar-cost-averaging)、[Schwab 擇時研究](https://www.schwab.com/learn/story/does-market-timing-work)

## 評分語意

建議三種並列資訊：

- 加碼支持度 1–10：目前規則對「額外分批買入」的支持程度；不是上漲機率、預期報酬或股票估值。
- 減碼支持度 1–10：獨立的趨勢惡化／過熱／再平衡訊號，不能直接等於 11 減買進分數。
- 風險與資料狀態：波動、槓桿、缺漏、最後交易日。不得把缺值偽裝成中性。

核心固定投入與額外機動加碼分開。每日更新觀察，每週或每月檢查行動；不代表每天交易。單一股票和正二 ETF 不自動套用大盤長期核心投入規則。

## 第一版指標清單與示意規則

以下分數、權重、確認天數是本案提出的待回測參數，並非來源的實證結果。每個指標都能顯示數值、參數、買／賣分數、觸發理由。先用 2/4/5/6/8 等少數等級，總分顯示一位小數，避免假精準。

| 指標 | 設定 | 買進支持示例 | 減碼支持示例 | 角色 |
|---|---|---|---|---|
| 長期均線 | SMA50/200；SMA200 與 20 個交易日前比較 | 價在 SMA200 上、均線上揚且 SMA50>SMA200：8；全反向：2；混合：5 | 價在 SMA200 下且 SMA200 下彎：8 | 趨勢 |
| 黃金／死亡交叉 | 昨日 SMA50≤SMA200、今日大於；反向為死亡交叉 | 黃金交叉且價在 SMA200 上：8；反向：2；無新事件：5 | 死亡交叉：8 | 顯示事件，不和均線另加一份權重 |
| RSI | Wilder RSI14 | 昨日≤30、今日>30：8；40–60 且上升：6；<30 且繼續下降：4；其餘：5 | 昨日≥70、今日<70：8；單純>70：5 | 進場時機 |
| KD | 台灣慣用 RSV9、K/D 遞迴 1/3 平滑，種子50 | K向上穿D且兩者<20：8；K>D：6；向下穿且兩者>80：2；其餘：5 | 高檔死亡交叉：8；低檔黃金交叉：2；其餘依狀態 | 進場時機，與RSI同組 |
| MACD | EMA12−EMA26，Signal EMA9 | Histogram>0 且上升：8；>0但下降：6；<0但上升：4；<0且下降：2；等值：5 | 上述反向動能作減碼支持 | 趨勢確認 |
| 布林通道 | SMA20 ± 2倍20日標準差 | 昨日低於下軌、今日回到軌內：8；只跌破下軌：4；其餘：5 | 從上軌外回到軌內：8；只突破上軌不直接賣 | 進場時機 |
| 距252日高點回落 | 同口徑調整收盤價 | <5%：4；5–10%：6；10–20%：8；≥20%：8並顯示高風險 | 不單獨導出賣出 | 回落程度；不是估值便宜 |
| ADX/DMI | Wilder14 | +DI>-DI且ADX≥25：8；反向：2；ADX<20或過渡：5 | 下跌趨勢確認 | 風險濾網，避免重複投票 |
| ATR% | Wilder ATR14/close | 不把高波動視為買進理由；如介面必須有分數則顯示「不適用」 | 歷史高分位提示降低機動部位 | 風險，不是方向 |
| 成交量／OBV | Volume/SMA20、OBV趨勢 | 可作突破驗證 | 可作下跌放量提示 | 第二版；大盤指數缺可靠量能時不計 |
| VIX | 原值、252日分位、5日變化 | 高分位且開始回落只作恐慌緩和提示 | 急升提示風險 | 美國背景；不直接套用亞洲市場 |
| CNN F&G | 原始0–100與日期 | 低檔回升作逆向情緒提示 | 高檔回落作過熱消退提示 | 選配；不是必要依賴 |

KD 公式：RSV=100×(C−9日最低)/(9日最高−9日最低)；K=2/3×前K+1/3×RSV；D=2/3×前D+1/3×K。分母為0時須明訂沿用前RSV，首次設50。不能直接拿 Stochastic(14,3,3) 當成同一版本。[CMoney公式](https://www.cmoney.com.tw/M_Table.aspx?CMenuID=M080)、[TradingView Stochastic](https://www.tradingview.com/support/solutions/43000502332-stochastic-stoch/)

所有交叉只在前一交易日至當前交易日發生時標記事件，另存距交叉幾個交易日；不能把連續站在線上每天都當成新黃金交叉。

## 綜合方式：分組而非指標數量投票

建議第一版只以可穩定取得的價格資料產生核心分數：

`加碼支持度 = 0.40×長期均線分 + 0.25×回落分 + 0.25×進場時機分 + 0.10×MACD分`

其中進場時機分為 RSI、KD、布林分數平均。黃金交叉歸均線組；ADX、ATR 為濾網；CNN 和 VIX 先只作情緒說明，不加入必要核心分。如此避免 RSI/KD/布林、MACD/均線，以及 CNN/VIX 各自重複計權。

例：均線8、回落8、進場時機7、MACD6，原始加碼分為7.55，顯示7.6。這是示例，非今日行情。

建議風險濾網：若收盤低於 SMA200 且 SMA200 下彎，機動加碼分上限6；再有 ADX≥25 且−DI>+DI，上限5；標註原始分、上限與理由。這不是禁止所有逆向投資，只是本版避免單憑超賣給出強加碼。

顯示區間：1–<3 額外買進支持弱；3–<5 觀望；5–<7 正常分批／等待確認；7–<9 支持機動分批加碼；9–10 保留給未來經驗證的更強條件，不刻意湊滿10。

高等級還要求至少3個價格組支持（各≥6），且有新收盤資料、至少連續3個交易日通過條件；休市和重跑不累積確認天數。這些門檻需要回測，不能當成功率保證。

減碼分另計：50%長期趨勢惡化＋30%短線反轉（RSI/KD/布林）＋20%MACD轉弱。高分顯示「檢查機動部位／是否再平衡」，不自動賣出長期核心；無持倉與目標配置資料時，不輸出具體賣幾張。過熱訊號與趨勢惡化分開解釋。若買與賣同時偏高，呈現訊號分歧而不是硬取平均。

## 槓桿與集中曝險

00631L、00685L 應有獨立槓桿頁籤和規則，不能將一般大盤分數直接翻譯為長期正二加碼。多數槓桿 ETF 每日重設，長期報酬不等於指數長期報酬乘二。[SEC投資人公告](https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-alerts/sec)

追蹤標的訊號與 ETF 自身價格/波動一起呈現；正二不列入預設核心定期投入。台積電、0050、台灣正二曝險重疊，不能視為多個獨立市場的確認票。指數是觀察基準，實際交易回測須用指定可交易商品。

## 資料正確性比指標數量優先

- 至少取得約400個交易日作指標暖機；策略評估盡量5–10年以上，受各商品成立日限制。收盤價不足以計算KD/ATR/ADX，必須要一致口徑的高低收盤。
- 原始價格用於當日顯示；拆分／除息調整價格用於連續技術序列，OHLC採同一調整因子；報酬評估另處理配息與現金流，避免重複計入。分割前後不能直接接原始價。
- 每筆保存市場、交易日、來源、取得時間、收盤狀態、調整口徑和規則版本。用各市場日曆判斷應有資料，不能把台灣假日套到美日韓。
- 每天08:00以當時可得的最近已完成交易時段為截止；美國與亞洲日期可以不同。休市沿用前值並標休市；應更新卻沒更新標異常，不發布新的分數。
- 抓取失敗有限重試；保留上一份成功資料並標過期；不得填0。來源切換需核對歷史口徑，不能任意拼接原始與調整價格。
- CNN缺失不影響核心價格評分；核心OHLC不足則該資產不評分。顯示有效指標覆蓋率，不以此冒充勝率。

## 回測怎麼判斷值得用

1. 比較固定每月投入、相同現金流的訊號加碼、單純長期均線規則。額外投入的錢須事先納入相同總預算，不能靠多投入冒充策略超額報酬。
2. 多頭、空頭、盤整分開；按時間切開開發／驗證／未碰過的測試期，並做滾動樣本外評估，少量候選參數即可，避免挑歷史最漂亮的組合。
3. 回測只能用訊號產生時已取得的資料。08:00訊號的成交價使用之後第一個允許交易時間，不能假設成交於用來算訊號的昨日收盤價。美股訊號不能回填成前夜可交易。
4. 台股成本、稅費、美股/日韓交易成本、滑價和台幣換匯成本明確建模；費率在實作時按交易商品查證。不能用不可交易指數的無成本回報等同實際投資績效。
5. 報告資產終值、金額加權報酬XIRR、時間加權報酬、最大回撤、現金比重、換手率、樣本數，及訊號後3/6/12月報酬分布。不要只列勝率或一般CAGR。
6. CNN若缺可靠逐日歷史，先不回測情緒版本；不得把今日回填/事後修訂資料當成當時已知。若沒有足夠證據，保留為觀察分數，不宣稱優於定期定額。

## 排程與免費部署

- 依原需求：台灣週一至週五08:00；UTC cron為 `0 0 * * 1-5`。目前GitHub也支援IANA timezone，仍可選用簡單UTC寫法。[GitHub排程](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)
- 08:00是觸發時間，網站更新要等抓取/計算/部署完成；GitHub明示整點尖峰可能延遲、甚至丟棄工作。若要求08:00已準備好，可另選07:45啟動，但需使用者同意改時間。
- 僅週一至週五會在週一才處理美國週五收盤；若要隔天可見，建議可選週一至週六 `0 0 * * 1-6`。未確認前維持原週一至週五需求。
- 公開repo排程在60天無活動會停用；設手動重跑和更新狀態提示。排程工作放預設分支；避免依賴快取作唯一歷史存檔。
- 公開repo的標準GitHub runner免費；私人repo有方案額度與儲存限制。一般Linux每日一次、小型快取和短保留artifact即可，不需要大型runner。[GitHub費用](https://docs.github.com/en/billing/concepts/product-billing/github-actions)
- GitHub Free的Pages可用公開repo；網站上限1GB、軟性月流量100GB。這種小型靜態研究站通常足夠；商業SaaS用途另受限制。[Pages限制](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)
- Cloudflare Pages Free目前每月500次build、一次1個build。每日更新約22–26次，另加開發建置亦通常足夠。[Cloudflare限制](https://developers.cloudflare.com/pages/platform/limits/)
- 免費使用平台子網域；自購網域另計費。建議GitHub Actions一次完成下載→驗證→計算→產出→部署；GitHub Pages最少帳號設定，Cloudflare Pages適合既有Cloudflare使用者。兩者不用同時部署。
- API金鑰只放Actions Secrets；瀏覽器只讀已生成JSON。公開repo不要存未允許再散布的行情資料；私人repo部署公開站也仍需確認公開顯示權。
